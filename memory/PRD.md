# CBE Planner - Product Requirements Document

## Overview
A competency-based education lesson planning system for Kenyan teachers with M-Pesa wallet payments, Firebase authentication, and MongoDB Atlas database.

## Architecture
- **Frontend**: React Native (Expo) - Cross-platform (Android, Web)
- **Backend**: FastAPI (Python) on port 8001
- **Database**: MongoDB (Motor async)
- **Auth**: Firebase Authentication
- **Payments**: Safaricom Daraja API (M-Pesa)

## Collections
- `users`, `wallets`, `wallet_ledger`, `wallet_transactions`
- `grades`, `subjects`, `strands`, `substrands`, `slos`
- `slo_mappings`, `learning_activities`, `competencies`, `values`, `pcis`
- `substrand_lessons` (legacy lesson config)
- `lesson_slos` (NEW - lesson-level curriculum intelligence)
- `lesson_plans`
- `schemes`, `scheme_drafts` (NEW - draft workflow)
- `notes`, `assessment_methods`

## Lesson SLO System (April 14, 2026)

### Architecture
- **Service layer**: `lesson_slo_service.py` — sync, auto-generation, CRUD
- **Collection**: `lesson_slos` with unique index on `(substrandId, lessonNumber)`
- **Auto-sync**: When admin accesses substrand or updates `number_of_lessons`, lesson SLOs are auto-generated as drafts
- **Admin editing**: Marks records as `isDraft=False, isAutoGenerated=False` — protected from regeneration
- **Regeneration**: Only replaces auto-generated drafts, never admin-edited ones

### Endpoints
- `GET /api/admin/lesson-slos/{substrand_id}` — list + auto-sync
- `PUT /api/admin/lesson-slos/{substrand_id}/{lesson_number}` — upsert single
- `POST /api/admin/lesson-slos/{substrand_id}/bulk` — bulk upsert
- `POST /api/admin/lesson-slos/{substrand_id}/regenerate` — force regenerate drafts
- `POST /api/admin/lesson-slos/{substrand_id}/sync` — non-destructive sync
- `POST /api/admin/lesson-slos/bootstrap` — migration for existing data

## Scheme Draft Workflow (April 14, 2026)

### Flow
1. User generates scheme via `POST /api/schemes/generate-v2`
2. Frontend calls `POST /api/schemes/save-draft` to persist
3. User reviews via `GET /api/schemes/drafts/{id}`
4. User previews PDF via `POST /api/schemes/drafts/{id}/preview` (FREE)
5. If unsatisfied, user edits topics and regenerates via `POST /api/schemes/drafts/{id}/regenerate`
6. User downloads via `POST /api/schemes/drafts/{id}/download` (KES 15)
7. Re-downloads of paid drafts are free

### Endpoints
- `POST /api/schemes/save-draft` — save generated scheme as draft
- `GET /api/schemes/drafts` — list user's drafts
- `GET /api/schemes/drafts/{id}` — get single draft
- `POST /api/schemes/drafts/{id}/regenerate` — update draft
- `POST /api/schemes/drafts/{id}/preview` — preview PDF (free)
- `POST /api/schemes/drafts/{id}/download` — download PDF (KES 15 first time)

## Scheme Generation Integration
- `generate_scheme_v2` prefers `lesson_slos` outcomes over parent SLOs
- Key inquiry questions: lesson_slo authored > auto-generated from outcome > fallback
- Learning experiences/resources/assessments: lesson_slo overrides > learning_activities > fallback

## Lesson Plan Integration
- `generate_lesson_plan` prefers `lesson_slos` for specific outcomes over legacy `substrand_lessons`
